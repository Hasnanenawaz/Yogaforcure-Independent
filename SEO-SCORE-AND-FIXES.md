## D. Remaining Improvements (Optional)

These are **not** blockers; they can push the score toward 90+ and improve UX/social sharing.

### 1. Open Graph / Twitter images

- **Current:** No `og:image` or `twitter:image` set.
- **Suggestion:** Add `openGraph.images` and `twitter.images` in `app/page.tsx` and `app/gallery/layout.tsx` (e.g. hero image or logo) so shares show a preview image.

### 2. Root layout metadata

- **Current:** Root layout has default title "Yoga for Cure by Neha" and a generic description. Child routes (home, gallery) override with their own metadata.
- **Suggestion:** Optionally align root default title/description with the primary brand (e.g. "Yoga by Neha | Yoga for Cure") so any route without its own metadata still has consistent branding. Low priority while only indexable pages have layout-level metadata.

### 3. Gallery layout shift (CLS)

- **Current:** Gallery uses masonry; layout can shift when images load.
- **Suggestion:** Keep or refine skeleton/min-height placeholders so CLS stays low. Monitor in PageSpeed Insights after deploy.

### 4. LCP image priority

- **Current:** Hero and SplashScreen use priority where appropriate.
- **Suggestion:** Confirm hero-section.webp (desktop) and mobile hero background are not delayed by other resources. Preload already used for splash image in root layout.

### 5. Structured data on gallery (optional)

- **Current:** No schema on `/gallery`.
- **Suggestion:** If gallery is a key landing page, consider **ImageGallery** or **ItemList** schema for the media. Optional for 90+ score.
